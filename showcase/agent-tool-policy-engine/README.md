# Agent 工具策略引擎｜執行前先檢查操作範圍

當 AI Agent 能讀寫檔案、執行命令或呼叫 API 時，不能只依靠提示詞要求它「小心一點」。哪些操作可以直接執行、哪些必須先經過確認，應該有可檢查的規則。

這個專案用 Python 實作**工具操作前的策略判斷核心**，將操作內容轉成結構化資料，再依規則給出決策。

## 核心概念

例如，讀取專案內的 Git 狀態可能可以直接執行；但修改受保護檔案、越過指定工作區或觸發高風險操作，就應該先檢查限制或取得核准。

決策分成四種：

| 結果 | 說明 |
| --- | --- |
| 允許（`allow`） | 符合規則，可執行 |
| 限定範圍（`allow_scoped`） | 只允許指定路徑或資源 |
| 人工核准（`require_approval`） | 執行前需由人確認 |
| 拒絕（`deny`） | 不符合政策，不執行 |

## 如何實作

政策寫在獨立的 [TOML 規則檔](policies/policy.toml)；[評估程式](src/agent_policy/evaluator.py) 依操作類型、路徑、分支及外部目標判斷。對相同的結構化輸入與政策，程式能提供一致的判定結果。

公開版本包含 [自動化測試](tests/test_policy.py)，也可作為 CLI 或 MCP 工具入口前的預檢元件。

## 使用邊界

這是**策略判斷元件**，不是作業系統沙盒，也不會自動控制所有 AI Agent。要真正阻止不允許的操作，仍須由執行工具的系統接入這個檢查結果並落實限制。
